# Neural interpolation candidates

Research checked 2026-11-17. Primary sources only; no models downloaded, builds performed, or inference run in this survey. Recommendations below are engineering judgments. None establishes real-time operation on our Arc A310 or Apple M5, or improved shirt/suit quality on the project clips.

Start with **RIFE**, followed by **IFRNet** as a second practical implementation. **EMA-VFI-small_t** is an attention-based challenger if porting effort is affordable. **AMT-S GoPro**, **FILM**, and **GIMM-VFI** are useful quality or motion-model references, with greater deployment constraints. These are different architectures within predominantly motion-guided neural interpolation; RIFE and IFRNet should not be counted as unrelated algorithm families.

| Priority | Candidate and useful distinction | Time/checkpoint contract | Portability and license evidence |
|---|---|---|---|
| 1 | **Practical RIFE 4.25 / 4.25.lite**, with **RIFE 4.6** as a portable baseline. Direct learned intermediate flow and image synthesis. | The Practical-RIFE author currently recommends 4.25 for most scenes; `lite` lowers computational cost. Pin matching downloaded architecture files and weights. RIFE v4 supports arbitrary time; verify the chosen export and scheduler. | Practical-RIFE explicitly applies MIT to its linked model downloads as well as the project. Current vs-mlrt exposes 4.25/lite and newer variants. The original ncnn port lists models only through 4.6: newer practical weights are not established drop-in replacements. [Practical RIFE](https://github.com/hzwer/Practical-RIFE), [vs-mlrt wrapper](https://github.com/AmusementClub/vs-mlrt/blob/master/scripts/vsmlrt.py), [ncnn port](https://github.com/nihui/rife-ncnn-vulkan). |

## Practical runtime routes

**Arc:** start with an established RIFE ONNX export through OpenVINO GPU, or the RIFE 4.6 ncnn Vulkan implementation as an independent portable baseline. The [vs-mlrt project](https://github.com/AmusementClub/vs-mlrt) explicitly lists Intel integrated/discrete GPUs for OpenVINO and ncnn Vulkan. Its current [wrapper](https://github.com/AmusementClub/vs-mlrt/blob/master/scripts/vsmlrt.py) includes 4.25/lite/4.26 choices and a time-mask `RIFEMerge` interface. This is stronger implementation evidence than assuming the authors' CUDA scripts will run unchanged on Intel.

**Mac:** ncnn Vulkan has an explicit MoltenVK build path. Alternatively, vs-mlrt advertises an ONNX Runtime CoreML backend for Apple SoCs. Use a static-shape MLProgram export and inspect actual operator placement before interpreting a timing result: ONNX Runtime documents CoreML compute-plan profiling, and enabling its Neural Engine option does not guarantee whole-model ANE execution. Its MLProgram support includes constrained `GridSample` support. This makes CoreML a concrete route to investigate, not a verified full-acceleration claim for RIFE on M5. [ncnn build instructions](https://github.com/nihui/rife-ncnn-vulkan), [CoreML execution-provider documentation](https://onnxruntime.ai/docs/execution-providers/CoreML-ExecutionProvider.html).

The ncnn command-line tools consume images/folders; their FFmpeg recipes extract and re-encode image sequences. A useful offline comparison can use that interface, but PNG I/O must be excluded from a model timing and included separately in pipeline timing. Real-time Cadence needs a native frame-buffer adapter and controlled transfers. The IFRNet port also lists UHD mode as unfinished despite exposing a CLI switch: do not assume that switch supplies a validated high-resolution optimization. [IFRNet port documentation](https://github.com/nihui/ifrnet-ncnn-vulkan).

## Checkpoint, scheduling, and quality boundaries

- Pin source revision, exact architecture, checkpoint hash, export hash, runtime, precision, padding, input range, resize settings, TTA settings, and device placement. A model name alone is not a reproducible experiment.
- Test actual requested timestamps. A CLI output-FPS flag can relabel playback without producing the required intermediate times. Midpoint recursion cannot exactly implement the non-dyadic phases needed for 24→60. FILM is a concrete source-verified example; its time-shaped API is not evidence of arbitrary-time synthesis. [FILM implementation](https://github.com/google-research/frame-interpolation/blob/main/models/film_net/interpolator.py).
- For IFRNet and AMT, the arbitrary-time GoPro training/checkpoints and midpoint Vimeo90K checkpoints are separate comparisons, rather than a harmless option change. The official IFRNet [8× demo](https://github.com/ltkong218/IFRNet/blob/main/demo_8x.py) exercises non-midpoint times; AMT's [model table](https://github.com/MCG-NKU/AMT) explicitly separates fixed and arbitrary models.
- EMA-VFI's [arbitrary-time demo](https://github.com/MCG-NJU/EMA-VFI/blob/main/demo_Nx.py) uses `ours_t` and offers `ours_small_t`; TTA settings differ in the example configurations. Record those settings when comparing quality and speed.
- The useful first visual question remains whether translated clothing/faces stay stable over time. Frame-wise PSNR or a better looking isolated midpoint does not establish that. Preserve retained frames exactly where timestamps coincide; assess synthesized-frame contrast/shape behavior and the complete output sequence.
- Perceptual/style objectives can improve apparent sharpness while changing pixel or material fidelity. Keep those checkpoints distinct from reconstruction-oriented ones. A neural model's internal flow is not automatically a calibrated physical motion measurement. For the sense-organ project, compare exposed fields against known synthetic motion independently of the final image.

The narrowest first block is a short **RIFE 4.6 portable baseline plus Practical RIFE 4.25/lite** quality comparison against the currently visible MCI reference, with exact time phases and colors held fixed. Promote only successful candidates to native-buffer timing on both devices. IFRNet GoPro supplies the next independent implementation; attention, all-pairs multi-field, and implicit-motion candidates then answer specific quality questions rather than expanding the benchmark matrix indiscriminately.
